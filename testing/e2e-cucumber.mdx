Fineract's end-to-end (E2E) test suite uses [Cucumber 7.34.3](https://cucumber.io/) with the JUnit Platform engine to execute Gherkin scenarios against a running Fineract server. The suite is split across two Gradle modules: `fineract-e2e-tests-core` contains all step definitions, hooks, initializers, and helper data classes; `fineract-e2e-tests-runner` contains the `TestRunner`, feature files, and the Gradle `cucumber` task that orchestrates execution. This separation allows the core step definitions to be reused in custom extension projects by adding a dependency on `:fineract-e2e-tests-core`.

## `TestRunner.java`

`TestRunner` is the JUnit 5 suite entry point for the E2E tests in `fineract-e2e-tests-runner`:

```java
// fineract-e2e-tests-runner/src/test/java/org/apache/fineract/test/TestRunner.java
@Suite
@IncludeEngines("cucumber")
@SelectPackages("org.apache.fineract.test")
@SelectDirectories("src/test/resources/features")
@ExcludeTags("Skip")
@ConfigurationParameter(key = PLUGIN_PROPERTY_NAME, value = "pretty")
@ConfigurationParameter(
    key = GLUE_PROPERTY_NAME,
    value = "org.apache.fineract.test.stepdef, " +
            "org.apache.fineract.test.stepdef.common, " +
            "org.apache.fineract.test.stepdef.hook, " +
            "org.apache.fineract.test.stepdef.loan, " +
            "org.apache.fineract.test.stepdef.saving, " +
            "org.apache.fineract.test.config"
)
public class TestRunner {}
```

The `@ExcludeTags("Skip")` annotation causes any scenario tagged `@Skip` to be silently omitted. All feature files under `src/test/resources/features/` are discovered automatically via `@SelectDirectories`.

## Client Library: `fineract-client-feign`

Step definitions call the Fineract API through the generated `fineract-client-feign` module rather than raw HTTP. `ApiProperties` binds the server coordinates from `fineract-test-application.properties`:

```java
// fineract-e2e-tests-core/.../api/ApiProperties.java
@Component
@Getter
public class ApiProperties {
    @Value("${fineract-test.api.base-url}")
    private String baseUrl;           // default: https://localhost:8443

    @Value("${fineract-test.api.username}")
    private String username;           // default: mifos

    @Value("${fineract-test.api.password}")
    private String password;           // default: password

    @Value("${fineract-test.api.tenant-id}")
    private String tenantId;           // default: default

    @Value("${fineract-test.client-read-timeout}")
    private long readTimeout;          // default: 60 (seconds)
}
```

## Lifecycle Hooks

`InitializingHook` (package `org.apache.fineract.test.stepdef.hook`) drives the global test setup and teardown via Cucumber JUnit 5 lifecycle annotations:

```java
// InitializingHook.java
@Slf4j
@SuppressWarnings({ "HideUtilityClassConstructor" })
public class InitializingHook {

    @BeforeAll
    public static void beforeAll() throws Exception {
        StandardEnvironment environment = new StandardEnvironment();
        environment.getPropertySources().addFirst(
            new ResourcePropertySource("classpath:fineract-test-application.properties"));
        InitializerProperties initializerProperties = PropertiesFactory.get(environment, InitializerProperties.class);
        if (initializerProperties.isEnabled()) {
            log.info("Setting up global defaults for Fineract");
            FineractInitializerFactory.get().setupGlobalDefaults();
        } else {
            log.info("Skipping global defaults for Fineract");
        }
        FineractInitializerFactory.get().setupDefaultsForSuite();
    }

    @Before
    public static void before() throws Exception {
        FineractInitializerFactory.get().setupDefaultsForScenario();
    }

    @After
    public static void after() throws Exception {
        FineractInitializerFactory.get().resetDefaultsAfterScenario();
    }

    @AfterAll
    public static void afterAll() throws Exception {
        FineractInitializerFactory.get().resetDefaultsAfterSuite();
    }
}
```

Global initialization (controlled by `INITIALIZATION_ENABLED=true`) runs the `*GlobalInitializerStep` classes to pre-create loan products, charge templates, delinquency buckets, GL accounts, currencies, and funds that scenarios rely on. When disabled, the test suite assumes these objects already exist (typical in CI where the database is seeded once).

## Running Cucumber E2E Tests

Start a Fineract instance (see [Docker & Kubernetes →](/deployment/docker-kubernetes)), then invoke the `cucumber` task from the runner module:

```bash
# Run all E2E tests against localhost:8443
./gradlew :fineract-e2e-tests-runner:cucumber

# Run a single feature file
./gradlew :fineract-e2e-tests-runner:cucumber \
  -Pcucumber.features=src/test/resources/features/Loan-Part1.feature

# Run scenarios matching a tag
./gradlew :fineract-e2e-tests-runner:cucumber \
  -Pcucumber.tags="@LoanFeature and @Smoke"

# Run against a non-default server
BASE_URL=https://staging.example.com:8443 \
TEST_USERNAME=admin \
TEST_PASSWORD=secret \
./gradlew :fineract-e2e-tests-runner:cucumber
```

The `cucumber` task is configured in `fineract-e2e-tests-runner/build.gradle`:

```groovy
cucumber {
    featurePath = project.hasProperty("cucumber.features")
        ? project.getProperty("cucumber.features")
        : "src/test/resources/features"

    tags = project.hasProperty("cucumber.tags")
        ? [project.getProperty("cucumber.tags")]
        : 'not @Skip'

    plugin = ['pretty', 'io.qameta.allure.cucumber7jvm.AllureCucumber7Jvm']
}
tasks.named('cucumber').get().finalizedBy 'allureReport'
tasks.named('cucumber').get().dependsOn 'spotlessCheck'
```

After a run, the [Allure](https://allurereport.org/) report is generated at `fineract-e2e-tests-runner/build/allure-report/`.

### CI Workflow

`.github/workflows/build-cucumber.yml` runs the full E2E suite in CI. The workflow builds the Docker image, starts the stack via `docker-compose-postgresql.yml`, waits for the actuator health endpoint, then runs:

```bash
./gradlew :fineract-e2e-tests-runner:cucumber
```

Allure results are archived as a workflow artifact on failure.

## Scenario Structure

A typical loan scenario in `Loan-Part1.feature` demonstrates the Gherkin style:

```gherkin
@LoanFeature
Feature: Loan - Part1

  @TestRailId:C16 @Smoke
  Scenario: Loan creation functionality in Fineract
    When Admin sets the business date to the actual date
    When Admin creates a client with random data
    When Admin creates a new Loan

  @TestRailId:C17
  Scenario: Loan creation functionality in Fineract
    When Admin sets the business date to "1 July 2022"
    When Admin creates a client with random data
    And Admin successfully creates a new customised Loan submitted on date: "1 July 2022",
        with Principal: "5000", a loanTermFrequency: 24 months, and numberOfRepayments: 24
```

TestRail IDs (`@TestRailId:C16`) are attached as tags, enabling the `TestRailLifecycleHook` (in `stepdef/hook/`) to report results back to TestRail when `TESTRAIL_ENABLED=true`.

## Parallel Execution Configuration

`junit-platform.properties` in the runner's resources controls parallel execution settings:

```properties
# junit-platform.properties
cucumber.execution.parallel.enabled=false
cucumber.execution.parallel.config.strategy=fixed
cucumber.execution.parallel.config.fixed.parallelism=3
cucumber.execution.exclusive-resources.isolated.read-write=\
  org.junit.platform.engine.support.hierarchical.ExclusiveResource.GLOBAL_KEY
cucumber.execution.execution-mode.feature=same_thread
```

Parallel execution is disabled by default because many scenarios mutate shared global state (business date, global configuration). Scenarios that are safe to run concurrently are not yet individually tagged for parallelism.
