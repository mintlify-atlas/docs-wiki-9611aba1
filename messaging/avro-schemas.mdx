All external events published from Fineract's outbox are serialized using [Apache Avro](https://avro.apache.org/). The `fineract-avro-schemas` Gradle subproject owns every `.avsc` schema definition and is responsible for generating the corresponding Java `SpecificRecord` classes at build time via the `com.github.davidmc24.gradle.plugin.avro` plugin. Downstream consumers can depend directly on this artifact to deserialize events without reimplementing the schema.

## Module Location

Schema source files live under:

```
fineract-avro-schemas/src/main/avro/
```

Gradle code generation places the resulting Java classes in:

```
fineract-avro-schemas/build/generated-main-avro-java/org/apache/fineract/avro/
```

## Message Envelope Schemas

Three top-level envelope schemas define how a single event or a batch of events are wrapped for the broker.

### MessageV1.avsc

The standard single-event envelope. Every individual event is serialized as a `MessageV1` record before being sent to Kafka or JMS:

```json
{
  "name": "MessageV1",
  "namespace": "org.apache.fineract.avro",
  "type": "record",
  "fields": [
    { "name": "id",           "doc": "ID of the outbox row",          "type": "long" },
    { "name": "source",       "doc": "Unique identifier of the source service", "type": "string" },
    { "name": "type",         "doc": "Event type, e.g. LoanApprovedBusinessEvent", "type": "string" },
    { "name": "category",     "doc": "Domain category, e.g. LOAN",    "type": "string" },
    { "name": "createdAt",    "doc": "UTC ISO_LOCAL_DATE_TIME",        "type": "string" },
    { "name": "businessDate", "doc": "ISO_LOCAL_DATE business date",   "type": "string" },
    { "name": "tenantId",     "doc": "Source tenant identifier",       "type": "string" },
    { "name": "idempotencyKey","doc": "Consumer de-duplication key",   "type": "string" },
    { "name": "dataschema",   "doc": "Fully qualified Avro class name","type": "string" },
    { "name": "data",         "doc": "Payload bytes (nested Avro)",    "type": "bytes" }
  ]
}
```

The `dataschema` field carries the fully qualified class name of the nested payload record (e.g., `org.apache.fineract.avro.loan.v1.LoanAccountDataV1`). Consumers use this to select the correct `SpecificRecord` class for deserializing `data`.

### BulkMessagePayloadV1.avsc and BulkMessageItemV1.avsc

For COB batch processing and other bulk operations, multiple events are packed into a `BulkMessagePayloadV1`, which wraps an array of `BulkMessageItemV1` records:

```json
// BulkMessagePayloadV1.avsc
{ "name": "BulkMessagePayloadV1", "namespace": "org.apache.fineract.avro",
  "fields": [{ "name": "datas", "type": { "type": "array", "items": "org.apache.fineract.avro.BulkMessageItemV1" } }] }

// BulkMessageItemV1.avsc (item fields: id, type, category, dataschema, data)
```

A bulk message is identified by `type = "BulkBusinessEvent"` and `category = "BULK_BUSINESS_EVENTS"` in the `MessageV1` envelope.

## BusinessEventSerializer: Mapping Events to Avro

The `BusinessEventSerializer` interface in `fineract-core/.../event/external/service/serialization/serializer/BusinessEventSerializer.java` defines the contract:

```java
public interface BusinessEventSerializer {
    <T> boolean canSerialize(BusinessEvent<T> event); // type check
    Class<? extends GenericContainer> getSupportedSchema(); // Avro record class
    <T> ByteBufferSerializable toAvroDTO(BusinessEvent<T> rawEvent); // convert to Avro DTO
}
```

`BusinessEventSerializerFactory` holds all serializer beans and selects the correct one by calling `canSerialize(event)` in sequence. Each domain module contributes its own `BusinessEventSerializer` implementations — for example, the loan module has serializers for `LoanApprovedBusinessEvent` → `LoanAccountDataV1`, `LoanTransactionMakeRepaymentPostBusinessEvent` → `LoanTransactionDataV1`, and so on.

The `toAvroDTO` method populates the Avro SpecificRecord from the event's aggregate root. For example, a loan approval serializer calls the loan's read service to produce a `LoanAccountDataV1` populated with the current account state at the moment of the event.

## Consuming Events

Consumers receive a `MessageV1` Avro record. The deserialization pattern is:

```java
// 1. Deserialize the outer MessageV1 envelope
MessageV1 envelope = MessageV1.fromByteBuffer(ByteBuffer.wrap(messageBytes));

// 2. Use dataschema to identify the payload type
String schemaClass = envelope.getDataschema(); // e.g. "org.apache.fineract.avro.loan.v1.LoanAccountDataV1"

// 3. Deserialize the nested payload
LoanAccountDataV1 payload = LoanAccountDataV1.fromByteBuffer(
    ByteBuffer.wrap(envelope.getData().array()));
```
